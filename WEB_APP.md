# Кабинеты проектирования курсов

[Кабинет преподавателя](http://127.0.0.1:8501/teacher) · [Кабинет эксперта](http://127.0.0.1:8501/expert)

## Запуск

В корне проекта заполните .env по .env.example. SESSION_SIGNING_KEY — постоянный случайный секрет длиной от 32 символов. В production задайте HTTPS-адрес PUBLIC_ORIGIN для ссылок-приглашений.

Кабинеты и воркеры при запуске сами создают таблицы в пустой БД приложения (по умолчанию `data/application.sqlite`). Существующую базу они не изменяют. Миграцию можно применить и вручную:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

Для локальной работы запустите три команды в отдельных терминалах из корня проекта.

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
.\.venv\Scripts\python.exe -m workers.course_worker
.\.venv\Scripts\python.exe -m workers.relevance_scheduler
```

Альтернатива для Docker — `docker compose up -d --build`. Сервис migrate применяет миграцию перед запуском кабинетов, обработчика и планировщика. Том course-data хранит SQLite и checkpoints. Для PostgreSQL укажите асинхронный APP_DATABASE_URL для SQLAlchemy и CHECKPOINT_URL в формате postgresql:// для LangGraph; на Windows с PostgreSQL используйте совместимый с psycopg SelectorEventLoop.

## Учётные записи

TEACHERS_INDEX_ID и EXPERTS_INDEX_ID указывают на раздельные ролевые справочники Yandex. Приложение читает исходные TXT через Files API и сопоставляет нормализованный логин целиком. Роль определяется индексом. Дублирующийся логин блокирует загрузку справочника. Снимок для входа кешируется в процессе веб-сервера до 30 секунд. Регистрации в кабинете нет.

Фактический формат TXT — пары строк «Логин» и «Пароль», разделённых двоеточием. Вариант «Логин» и «password_hash» поддерживает Argon2id, bcrypt и PBKDF2-SHA256. В облачных TXT с полем «Пароль» исходные пароли доступны читателям файлов. Для перехода на хеши владелец справочников может подготовить новые TXT с теми же логинами и полем password_hash, обновить соответствующие файлы и проверить вход. При такой замене сохраняются идентификаторы владельцев курсов. Приложение читает файлы без записи. В SQL сохраняются сессии, попытки входа, события и состояние курсов. Пароли и файлы справочников в граф не передаются.

## Работа с курсом

1. Преподаватель открывает «Создать курс», вводит профессию или курс, вуз, учебный год и при необходимости обязательные предметы. Кнопка «✨ Добавить предметы автоматически» запускает подбор и проектирование. Воркеры продолжают работу после закрытия вкладки.
2. Business получает рабочие задачи из Priklad и HH, Science подбирает статьи, University и Books дают академические источники. При достаточном покрытии граф формирует программу и бизнес-аудит. При пробеле в данных появляется вопрос и возможность пригласить существующего эксперта.
3. Эксперт входит по ссылке или через свой кабинет, отвечает в чате и нажимает «Завершить интервью и передать в курс». После проверки утверждений возможен следующий вопрос. Интервьюер получает методики из Interview.
4. В «Ваши курсы» преподаватель открывает черновик, проверяет темы, задания и ссылки. Добавления и изменения выделены оранжевым. В поле «Что изменить или уточнить» можно приложить до трёх TXT, DOCX или PDF по 10 МБ. Перед утверждением можно указать подтверждённые часы и размер ЗЕ по дисциплине.
5. ZIP с отдельными РПД доступен после утверждения и проверки официальных материалов по каждой дисциплине. При недоступности индекса RPD модель деятельности, интервью и черновик остаются доступны. В карточке версии нажмите «Перепроверить материалы РПД», затем «Обновить статус». Проверка проходит для этой версии без повторной генерации курса.

Через 270 дней запускается аудит актуальности. Предыдущая утверждённая версия доступна во время ревью. Новую версию можно утвердить, доработать или отклонить.

При временном сбое команды повторяются с задержкой, максимум пять попыток. В карточке курса отображаются причина и время следующей попытки в UTC. После исправления постоянной ошибки или исчерпания лимита кнопка «Повторить обработку» даёт той же команде новый лимит. Выполненные этапы восстанавливаются из checkpoint.

Планировщик опрашивает БД раз в пять минут. Для разового вызова из cron используйте `python -m workers.relevance_scheduler --once`. Результаты и решения сохраняются в БД приложения; для восстановления после перезапуска сохраняйте также БД checkpoints. Кнопка «Обновить статус» перечитывает состояние курса.
