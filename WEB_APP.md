# Кабинеты проектирования курсов

[Кабинет методиста](http://127.0.0.1:8080/teacher) · [Кабинет эксперта](http://127.0.0.1:8080/expert)

## Запуск

В корне проекта заполните `.env` по `.env.example`. `SESSION_SIGNING_KEY` — постоянный случайный секрет длиной от 32 символов. При запуске на ВМ задайте HTTP-адрес с портом в `RPD_PUBLIC_ORIGIN` для ссылок-приглашений.

Курсы, версии, интервью, сессии и контрольные точки LangGraph по умолчанию хранятся в PostgreSQL. Укажите `APP_DATABASE_URL` в формате `postgresql://пользователь:пароль@хост:5432/база`. Пустой `CHECKPOINT_URL` направляет LangGraph в ту же базу. Для PostgreSQL в Docker задайте в `.env` случайный `POSTGRES_PASSWORD` из шестнадцатеричных символов и подставьте его в `APP_DATABASE_URL` для запуска с хоста. Секрет можно сгенерировать командой `python -c "from secrets import token_hex; print(token_hex(32))"`.

`docker compose up -d` запускает PostgreSQL, применяет миграции и запускает кабинеты, воркер и планировщик. Веб-приложение доступно по HTTP на порту `8080`. Контейнеры получают внутренний адрес базы автоматически. Том `postgres-data` содержит PostgreSQL. Том `course-data` хранит файлы приложения, в том числе прежние базы SQLite, если они были в этом томе.

Для локального Python запустите PostgreSQL отдельно (`docker compose up -d --wait postgres` или свой сервер с пустой базой). Из корня проекта примените миграции:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

Затем запустите три команды в отдельных терминалах из корня проекта.

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
.\.venv\Scripts\python.exe -m workers.course_worker
.\.venv\Scripts\python.exe -m workers.relevance_scheduler
```

При запуске напрямую через Streamlit откройте [http://127.0.0.1:8501](http://127.0.0.1:8501).

## Перенос существующих данных из SQLite

Остановите кабинеты, воркер и планировщик, чтобы файлы приложения и LangGraph соответствовали одному состоянию. Сохраните резервные копии `data/application.sqlite` и `data/checkpoints.sqlite`. Если рядом есть `-wal` или `-shm`, оставьте их рядом с исходными файлами на время переноса. Укажите пустую базу PostgreSQL в `APP_DATABASE_URL` и оставьте `CHECKPOINT_URL` пустым. Перенос с хоста:

```powershell
.\.venv\Scripts\python.exe -m scripts.migrate_sqlite_to_postgres
```

Для прежних SQLite-файлов в томе `course-data` используйте команды из корня проекта:

```powershell
docker compose stop app worker scheduler
docker compose up -d --wait postgres
docker compose build migrate
docker compose run --rm --no-deps migrate python -m scripts.migrate_sqlite_to_postgres
docker compose up -d
```

Команда снимает копии SQLite, применяет Alembic и переносит строки и историю LangGraph одной транзакцией. Если целевая база уже содержит данные приложения, команда прерывается. После переноса проверьте список курсов, версии и статусы в кабинете. Сохраните `SESSION_SIGNING_KEY`, чтобы существующие приглашения продолжили работать. Для последующих резервных копий PostgreSQL используйте `pg_dump` всей базы `rpd`.

## Учётные записи

TEACHERS_INDEX_ID и EXPERTS_INDEX_ID указывают на раздельные ролевые справочники Yandex. Приложение читает исходные TXT через Files API и сопоставляет нормализованный логин целиком. Роль определяется индексом. Дублирующийся логин блокирует загрузку справочника. Снимок для входа кешируется в процессе веб-сервера до 30 секунд. Регистрации в кабинете нет.

Фактический формат TXT — пары строк «Логин» и «Пароль», разделённых двоеточием. Вариант «Логин» и «password_hash» поддерживает Argon2id, bcrypt и PBKDF2-SHA256. В облачных TXT с полем «Пароль» исходные пароли доступны читателям файлов. Для перехода на хеши владелец справочников может подготовить новые TXT с теми же логинами и полем password_hash, обновить соответствующие файлы и проверить вход. При такой замене сохраняются идентификаторы владельцев курсов. Приложение читает файлы без записи. В SQL сохраняются сессии, попытки входа, события и состояние курсов. Пароли и файлы справочников в граф не передаются.

## Работа с курсом

1. Методист открывает «Создать курс», вводит профессию или курс, вуз, учебный год и при необходимости обязательные предметы. Кнопка «✨ Добавить предметы автоматически» запускает подбор и проектирование. Воркеры продолжают работу после закрытия вкладки.
2. Business получает рабочие задачи из Priklad, индекса HH и свежих вакансий «Работа в России» и Карьеры Яндекса. Science подбирает статьи, University и Books дают академические источники. При достаточном покрытии граф формирует программу и бизнес-аудит. При пробеле в данных появляется вопрос и возможность пригласить существующего эксперта.
3. Эксперт отвечает в чате и нажимает «Завершить интервью и передать в курс». После проверки ответа система собирает черновик по подтверждённым материалам. Пока курс ждёт эксперта, методист может нажать «Сформировать черновик по имеющимся данным».
4. В «Ваши курсы» методист открывает карточку курса и раздел «Черновик РПД». Оставшиеся пробелы помечены над дисциплинами. В «Проверке ответов эксперта» видны выводы по каждому утверждению и основания проверки. В поле «Что изменить или уточнить» можно приложить до трёх TXT, DOCX или PDF по 10 МБ.
5. После утверждения доступен ZIP с отдельными РПД в JSON и HTML, учебными данными и источниками. Через 270 дней запускается аудит. Предыдущая утверждённая версия доступна во время ревью. Новую версию можно утвердить, доработать или отклонить.

Планировщик опрашивает БД раз в пять минут. Для разового вызова из cron используйте `python -m workers.relevance_scheduler --once`. Результаты и решения сохраняются в БД приложения; для восстановления после перезапуска сохраняйте также БД checkpoints. Кнопка «Обновить статус» перечитывает состояние курса.

После формирования тем University подбирает к ним учебники и статьи. Ссылки и библиографические описания доступны в карточке и в ZIP. При недоступности поиска черновик сохраняется с примечанием. LITERATURE_PARSER_ENABLED=0 отключает подбор. LITERATURE_USE_LLM=1 включает расширение запросов моделью University. Платный Yandex Search включается отдельно через LITERATURE_YANDEX_SEARCH=1.

Отчёт по курсу показывает, зачем включена каждая дисциплина, с цитатами из индексов Books, RPD, Priklad и HH. Когда подтверждения в базе не хватает, это отмечено рядом с дисциплиной. Утверждённая версия включает в ZIP файл `course-report.html`.

Для новых курсов и планового аудита Business собирает вакансии за последние 45 дней. В оценке курса доступны даты и ссылки на карточки. Число вакансий и работодателей относится к собранной выборке. PUBLIC_VACANCIES_ENABLED=0 отключает оба открытых источника, EMPLOYER_CAREERS_ENABLED=0 оставляет только Роструд из открытых источников. Доступ к индексам Priklad и HH сохраняется.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip check
docker compose config --quiet
```

Для интеграционного теста миграции задайте `RPD_TEST_POSTGRES_URL` с доступом к тестовому PostgreSQL. Тест создаёт отдельную схему и проверяет возобновление прерванного интервью после переноса.
