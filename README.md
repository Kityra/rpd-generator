# Генератор РПД

Веб-приложение и набор CLI-инструментов для подготовки черновиков рабочих программ дисциплин (РПД). Проект собирает сведения из настроенных источников, координирует несколько профильных агентов через LangGraph и выдаёт документ, проверенный по JSON-схеме.

> Результат генерации — черновик для методической проверки. До утверждения необходимо сверить компетенции, формы аттестации, учебный план и источники с официальными материалами вуза.

## Модель деятельности профессии

Главный модуль системы — проверенная экспертами **модель деятельности профессии** (функции → задачи → знания и
инструменты → межпрофессиональные области знаний) и рекомендации руководителю образовательной программы:
создать, обновить, сократить, объединить дисциплины, сохранить фундамент, сигнал «профиль под риском».
Решения считает алгоритм по формулам и порогам [`config/activity_model.yaml`](config/activity_model.yaml);
LLM только извлекает утверждения с дословными цитатами, которые проверяет код. Подробности, запуск демо и
допущения — в [ACTIVITY_MODEL.md](ACTIVITY_MODEL.md).

```powershell
Copy-Item local_users.example.txt data\local_users.txt
.\.venv\Scripts\python.exe -m scripts.seed_activity_demo --reset
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Кабинеты: `/head` — руководитель программы, `/teacher` — методист, `/expert` — эксперт.

## Возможности

- подготовка РПД для одной дисциплины или комплекта дисциплин курса;
- подбор дисциплин по материалам учебного плана с возможностью вручную отредактировать список;
- работа трёх профильных узлов: University, Science и Business;
- поиск по индексам Yandex AI Studio и генерация структурированного ответа через Responses API;
- подбор свежих научных публикаций из Crossref и arXiv для учебных тем и практических заданий;
- правки к готовому черновику с вложениями TXT, DOCX и PDF;
- экспорт отдельной РПД в JSON и TXT, а комплекта — в ZIP-архив;
- отдельный пакет `rabota_it` для импорта разрешённых выгрузок ИТ-вакансий Работа.ру и локальной аналитики рынка.

## Быстрый старт

Нужен Python 3.11 или новее и доступ к Yandex AI Studio.

```powershell
git clone https://github.com/Kityra/rpd-generator.git
Set-Location rpd-generator
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните `.env` значениями своего каталога Yandex Cloud, затем запустите интерфейс:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Откройте [http://localhost:8501](http://localhost:8501). Данные черновиков в этом интерфейсе хранятся только в текущей вкладке браузера, поэтому перед закрытием вкладки скачайте нужные файлы.

## Настройка

Скопируйте `.env.example` в `.env`. Файл `.env` исключён из Git: не добавляйте в репозиторий ключи, пароли или реальные идентификаторы окружения.

| Переменная | Назначение |
| --- | --- |
| `YANDEX_API_KEY` | ключ сервисного аккаунта Yandex Cloud |
| `YANDEX_FOLDER_ID` | идентификатор каталога Yandex Cloud |
| `YANDEX_MODEL_URI` | URI модели, формирующей итоговый черновик |
| `YANDEX_VECTOR_STORE_ID_RPD` | индекс с примерами РПД и учебными сведениями |
| `YANDEX_VECTOR_STORE_ID_BOOKS` | необязательный индекс учебных и научных материалов |
| `YANDEX_VECTOR_STORE_ID_HH` | необязательный индекс сведений о востребованных навыках |
| `PROGRAM_HEADS_INDEX_ID` | необязательный справочник руководителей программ (формат как у методистов) |
| `LOCAL_USERS_FILE` | локальные учётные записи для разработки, только при `APP_ENV=development` |

Для профильных узлов можно отдельно задать `YANDEX_MODEL_URI_UNIVERSITY`, `YANDEX_MODEL_URI_SCIENCE` и `YANDEX_MODEL_URI_BUSINESS`. Если оставить их пустыми, используется Alice AI LLM Flash текущего каталога.

Перед первым запуском полезно проверить доступ к индексам:

```powershell
.\.venv\Scripts\python.exe check_yandex_indexes.py
.\.venv\Scripts\python.exe check_yandex_indexes.py --index rpd --query "Форма аттестации по дисциплине Базы данных"
.\.venv\Scripts\python.exe check_yandex_indexes.py --check-model
```

Подробные требования к ролям, индексам и ключам описаны в [YANDEX_AI_SETUP.md](YANDEX_AI_SETUP.md).

## Как устроена подготовка РПД

```text
Заявка методиста
        |
        v
  LangGraph-координатор
   /        |         \
University  Science  Business
   |           |         |
RPD/Books  Books +    HH
           Crossref,
           arXiv
        \    |    /
         Черновик РПД
              |
        Проверка схемой
              |
  правки → утверждение → экспорт
```

- **University** извлекает сведения о структуре РПД и учебные материалы.
- **Science** предлагает актуальные темы и задания по метаданным публикаций; полные тексты остаются у издателей и в arXiv.
- **Business** добавляет контекст востребованных навыков при наличии соответствующего индекса.
- Координатор формирует JSON по [`final_schema.json`](final_schema.json). Если обязательные официальные данные отсутствуют, интерфейс помечает их для сверки, а не подставляет как подтверждённые факты.

Подробнее о веб-интерфейсе — в [WEB_APP.md](WEB_APP.md), об устройстве и ограничениях пайплайна — в [PIPELINE_AUDIT.md](PIPELINE_AUDIT.md).

### Происхождение дисциплин и журнал вызовов модели

Каждый вызов модели записывается в таблицу `model_calls`: этап, модель, длительность, токены, итог
(`ok`, `validation_error`, `timeout`, `circuit_open`, `moderated`, `truncated`, `unavailable`, `error`) и текст
ошибки без ключей. Каждая дисциплина хранит `generated_by`: `model` или `outline`. Дисциплина с отметкой
`outline` собрана шаблоном из сохранённых материалов, потому что модель не ответила. В кабинете и экспорте она
помечена «Собрано шаблоном, нужна проверка» вместе с причиной. Дисциплины генерируются по одной; при таймауте
или паузе модели вызов повторяется через `DRAFT_RETRY_DELAYS` (по умолчанию 30 с, 2 мин и 5 мин).

### Отбор источников

Запрос к индексам строится из названия курса, профессии выпускника, ручных дисциплин и (при плановой проверке)
рабочих задач утверждённой версии. Оценка близости из векторного поиска хранится в источнике
(`relevance_score`). Фрагменты с оценкой ниже `VECTOR_MIN_SCORE`, а также служебные фрагменты — списки литературы,
таблицы трудоёмкости, оглавления — в реестр не попадают; об отброшенных фрагментах сообщает пометка в версии.

### Проверка смысла обоснований и состава курса

Цитата в обосновании дисциплины проходит две проверки:
- **Кодом.** Цитата не должна быть служебным фрагментом вроде таблицы часов или списка литературы. Она должна
  содержать понятия из названия дисциплины, с учётом словоформ и синонимов из
  [`config/analysis.yaml`](config/analysis.yaml), а объяснение должно опираться на неё.
- **Моделью‑судьёй** на быстрой модели: ответ `supports`, `weak` или `unrelated`.

Обоснование принимается только при `supports`. Иначе дисциплина помечается «требует проверки»
(`rationale_check`). Для состава курса код ищет дубли и почти‑дубли дисциплин и дисциплины без связи с
профессией и задачами. Флаг «фундаментальное ядро» требует источника РПД или учебника и ограничен долей
дисциплин. Покрытие задач источниками учитывает тип источника, свежесть и число независимых источников.

### Навыки рынка

Покрытие навыков рынка считает код в `orchestration/market_analysis.py` по реальным входным данным.
Модель в расчёте не участвует. Источников данных два:

1. **Загруженный файл.** Файл загружается в кабинете курса в разделе «Рыночные данные курса». Шаблоны лежат в
   [`templates/`](templates):
   - `market_data.json` — источник, регион, период, список навыков `skills` (`name`, `weight`, `vacancies`,
     `aliases`, `tasks`) и/или выборка вакансий `vacancies` (`title`, `skills`, `text`);
   - `market_skills.csv` — столбцы `skill;weight;vacancies;aliases;tasks`;
   - `market_vacancies.csv` — столбцы `title;skills;text`.

   Шаблоны пустые, заполните их своей выгрузкой. Коды стандартов не нужны.
2. **Карточки вакансий,** найденные для курса: Rostrud, карьерные сайты, Работа.ру, HH.

По этим данным считаются:
- доля вакансий с каждым навыком. Навыки распознаются по словарю
  [`config/market_skills.yaml`](config/market_skills.yaml): ИТ, финансы, продажи, инженерия и др.;
- деление навыков на критичные и дополнительные по порогу `critical_share`;
- покрытие навыка курсом: полное — навык есть в темах, частичное — только в заданиях, нет покрытия;
- непокрытые навыки, дисциплины без связи с рынком и задачами, приоритет навыков и задач по весу и дефициту
  покрытия;
- доля покрытых критичных навыков — расчётная оценка соответствия курса рынку.

Оценка модели из бизнес-аудита показывается отдельно и подписана как мнение. Если данных нет, отчёт сообщает
«рыночные данные не загружены» и не показывает чисел. Методист может вручную указать, какие дисциплины
покрывают навык.

## Командная строка

Подготовить один черновик РПД в интерактивном режиме:

```powershell
.\.venv\Scripts\python.exe run_rpd.py
```

Либо передать сведения явно:

```powershell
.\.venv\Scripts\python.exe run_rpd.py `
  --discipline "Базы данных" `
  --institution "Южный федеральный университет" `
  --year "2026/2027" `
  --facts-file .\facts.txt `
  --output .\rpd_draft.json
```

Подготовить РПД по перечню дисциплин и сформировать читаемый отчёт:

```powershell
.\.venv\Scripts\python.exe run_course.py `
  --course "Прикладная информатика" `
  --institution "Южный федеральный университет" `
  --year "2026/2027" `
  --disciplines-file .\disciplines.txt `
  --output-dir .\course_output
```

В `disciplines.txt` укажите по одной дисциплине на строку. Если файл не передать, сервис попробует подобрать состав курса по индексу РПД; в обоих случаях требуется заполненный `.env`.

Провести независимый обзор свежих ИТ-публикаций:

```powershell
.\.venv\Scripts\python.exe run_science.py
.\.venv\Scripts\python.exe run_science.py --area security
```

### Вакансии Работа.ру

Пакет `rabota_it` работает только с полным JSON-снимком из разрешённой выгрузки или договорного HTTPS-источника. Он не собирает вакансии со страниц сайта.

```powershell
.\.venv\Scripts\python.exe -m rabota_it import .\vacancies.json
.\.venv\Scripts\python.exe -m rabota_it search "разработчик Python" --region Москва --technology Docker
.\.venv\Scripts\python.exe -m rabota_it summary "разработчик"
```

Формат входных данных, ограничения источника и использование пакета из LLM-компонента описаны в [rabota_it/README.md](rabota_it/README.md).

## Запуск в Docker

Создайте и заполните `.env`, затем выполните:

```powershell
docker compose up --build
```

Compose публикует контейнер только на `127.0.0.1:8501`. В текущем коде режим с сетевым адресом намеренно отключает форму генерации до подключения облачного входа. Для локальной демонстрации используйте команду Streamlit из раздела «Быстрый старт». Для внешнего доступа понадобятся отдельные настройка HTTPS и аутентификация; не открывайте демонстрационный интерфейс в интернет без них.

## Проверка проекта

Снимки нормализованных источников хранятся в таблице `evidence_snapshots` базы `APP_DATABASE_URL`.
Для существующей базы перед перезапуском приложения и воркера примените миграцию:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

В Docker Compose миграцию выполняет сервис `migrate`. Чтобы проверить восстановление в тестовом окружении,
выполните поиск при доступном источнике, перезапустите воркер и повторите тот же запрос при временном
сбое источника. В результате должна быть отметка с исходной датой снимка. Срок годности — семь дней
для RPD и Books, одни сутки для HH и Priklad, шесть часов для Crossref и arXiv.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```
