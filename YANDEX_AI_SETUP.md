# Подключение LangGraph к Yandex AI Studio

LangGraph координирует подготовку РПД. Для генерации он обращается к модели Yandex AI Studio, а для поиска запрашивает напрямую существующие индексы Vector Store.

Устройство графа, результаты проверки и текущие ограничения описаны в [разборе пайплайна](PIPELINE_AUDIT.md).

Запуск текущего интерфейса Streamlit и состояние подключения облачных учётных записей описаны в [инструкции веб-приложения](WEB_APP.md).

## Нужные значения

- `YANDEX_API_KEY` — секрет сервисного аккаунта; хранить только в локальном `.env` или в секретах VPS.
- `YANDEX_FOLDER_ID` — ID каталога Yandex Cloud из адреса Model Gallery.
- `YANDEX_MODEL_URI` — URI модели. Стартовое значение использует Alice AI LLM из [каталога моделей](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models).
- `YANDEX_MODEL_URI_UNIVERSITY`, `YANDEX_MODEL_URI_SCIENCE`, `YANDEX_MODEL_URI_BUSINESS` — необязательные настройки модели для каждого профильного узла. По умолчанию все три используют Alice AI LLM Flash.
- `YANDEX_VECTOR_STORE_ID_RPD`, `YANDEX_VECTOR_STORE_ID_BOOKS`, `YANDEX_VECTOR_STORE_ID_HH` — идентификаторы существующих индексов. Их можно скопировать из Agent Core → Поисковые индексы.
- `YANDEX_BASE_URL` — `https://ai.api.cloud.yandex.net/v1`.

Шаблон переменных находится в `.env.example`. Для нового окружения скопируйте его в `.env` и заполните переменные вашего каталога. Секретный API-ключ не вставлять в Git, чат или файл-шаблон.

## Доступы сервисного аккаунта

Официальный пример Yandex для [поиска по существующему индексу](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/agents/vectorstore-search) использует `ai.assistants.editor` и `ai.languageModels.user`. Общий [справочник ролей](https://yandex.cloud/ru/docs/iam/roles-reference) также указывает право поиска у `ai.assistants.viewer`. Проверьте текущий доступ сервисного аккаунта прежде, чем менять его роли.

Для вызова [Responses API по базовому примеру](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/create-prompt) нужны `ai.languageModels.user` и область действия ключа `yc.ai.foundationModels.execute`. Пример прямого поиска использует ту же область ключа.

## Индексы проекта

| Индекс | Для чего использовать |
| --- | --- |
| RPD | Примеры рабочих программ дисциплин и их структура |
| Books | Книги и научные материалы для University и Science |
| HH | Сведения о вакансиях для анализа востребованных навыков |

## Проверка доступа к индексам

Если `.env` отсутствует, скопируйте `.env.example` в `.env`. Заполните `YANDEX_API_KEY` ключом сервисного аккаунта с доступом к этому каталогу.

```powershell
python -m pip install openai python-dotenv
python check_yandex_indexes.py
```

Скрипт читает [статус и счётчики файлов](https://aistudio.yandex.ru/ru/docs/ai-studio/api/Vector-stores/getVectorStore). Для проверки поиска укажите название дисциплины, которая есть в индексе, например:

```powershell
python check_yandex_indexes.py --index rpd --query "Форма аттестации по дисциплине Базы данных"
```

Запрос поиска покажет названия найденных файлов. Проверьте, что хотя бы один из них относится к нужной дисциплине. Чтобы также проверить вызов модели через [Responses API](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/create-prompt), запустите:

```powershell
python check_yandex_indexes.py --check-model
```

## Поток запроса

1. LangGraph принимает пользовательские сведения и параллельно запускает три профильных узла.
2. Узлы готовят отчёты с номерами исходных фрагментов и названием индекса. University использует RPD для вузовских сведений, а Books для учебных материалов и библиографии. Science использует Books и ищет публикации по дисциплине в Crossref и arXiv за последние 365 дней. Координатор получает учебные идеи Science и ссылки. Business использует HH для примеров востребованных навыков. При недоступности дополнительных источников подготовка РПД продолжается с доступными материалами.
3. Координатор получает отчёты и исходные фрагменты. Responses API получает производную схему ответа в режиме `strict: true`.
4. Приложение проверяет черновик по `final_schema.json`. В веб-приложении интервьюер направляет вопросы о недостающих сведениях профильному эксперту. Координатор продолжает работу с черновиком после получения ответа.

## Обзор исследований по ИТ для Science

Обзор запускается отдельно от подготовки РПД. Science ищет до пяти публикаций за последние 365 дней по ИИ, данным, безопасности, распределённым системам и разработке ПО. Crossref ищет кандидатов в стартовом списке профильных изданий. Например, для баз данных используются Proceedings of the VLDB Endowment и Proceedings of the ACM on Management of Data. arXiv ищет по категориям и даёт отдельные записи, для которых опубликованная версия ещё не проверена. Цитируемость используется при отборе внутри каждой области.

```powershell
.\.venv\Scripts\python.exe run_science.py
```

Параметр `--area` сужает обзор до `ai`, `data`, `security`, `systems` или `software`. Команда `run_science.py` пригодна для отдельной проверки источников из терминала. Поиск внутри РПД подбирает публикации под конкретную дисциплину. Для обоих сценариев используются метаданные, а полные тексты остаются у издателей и в arXiv.

- В `SCIENCE_VERIFIED_DOIS` можно перечислить через запятую DOI, для которых методист или эксперт подтвердил релевантность и рецензирование. Если DOI найден в результатах Crossref, приложение проверит наличие уведомления об отзыве статьи. Только подтверждённые карточки передаются модели Science для обзора. Остальные карточки доступны для сверки в выводе команды.
- `SCIENCE_SEMANTIC_SCHOLAR_ENABLED=1` и `SEMANTIC_SCHOLAR_API_KEY` включают дополнительную сверку числа цитирований для совпадающих DOI. Используйте эту настройку, если условия вашего ключа разрешают сценарий. Значения из Semantic Scholar остаются в приложении. При отсутствии ключа или недоступности сервиса приложение использует счётчик Crossref.

Ссылки на API: [Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/), [arXiv](https://info.arxiv.org/help/api/user-manual.html), [Semantic Scholar](https://api.semanticscholar.org/api-docs/).

## Интервью с экспертом в веб-приложении

1. Методист запускает подготовку РПД. По каждому существенному пропуску система сохраняет, какое поле нужно заполнить, вопрос и предметную область.
2. Приложение подбирает эксперта в справочнике по предметной области и отправляет запрос в его личный кабинет. Если подходящего эксперта в справочнике пока нет, методист видит статус «Ожидает назначения эксперта».
3. Эксперт входит по своей почте `@sfedu.ru` и паролю. В базе хранится уникальный адрес, хеш пароля и перечень предметных областей эксперта. Эксперт получает доступ к назначенным ему запросам.
4. Для запроса открывается отдельный чат эксперта с интервьюером. В нём эксперт видит вопросы и нужный контекст по дисциплине, отвечает текстом и может прикрепить файлы. Методист видит статус запроса и только почту `@sfedu.ru` из данных об эксперте.
5. Приложение сохраняет ответ и ссылки на вложения вместе с запросом и возобновляет тот же черновик в LangGraph. Граф использует полученные сведения и повторно проверяет РПД. Если открыто несколько запросов, каждый ответ учитывается отдельно, а сохранение итоговой РПД ждёт закрытия существенных пропусков.

Для этого сценария нужны справочник экспертов, учётные записи, отдельные чаты, хранилище вложений и сохранение состояния графа между входами. Правило выбора, если по одной области назначено несколько экспертов, определим при настройке справочника.

## Первый запуск координатора

В PowerShell откройте папку проекта и запустите:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_rpd.py
```

Введите название дисциплины, учебный год и вуз. Координатор соберёт материалы по трём профилям. Ответы в терминале имитируют ответ эксперта для локальной демонстрации графа. После проверки появится `rpd_draft.json`. Чтобы сохранить ещё один документ, укажите другое имя через `--output`.

Если уже есть сведения о программе, нагрузке и компетенциях, их можно сохранить в текстовый файл UTF-8 и передать параметром `--facts-file`. Результат — черновик для методической сверки. История интервью сохраняется в памяти текущего запуска. Веб-интерфейс и экспорт по PDF-шаблону относятся к следующим этапам.

## Веб-приложение и развёртывание

Итоговая поставка — приложение на Streamlit с запуском через Docker Compose на Ubuntu 24.04. Приложение должно открываться по домену проекта через HTTPS.

- Кабинет методиста позволяет запустить подготовку РПД, видеть статус запросов и скачать результат в JSON, DOCX, PDF и TXT. JSON проверяется по `final_schema.json` перед экспортом.
- Кабинет эксперта показывает его запросы и отдельные чаты с ответами и вложениями. Вход эксперта осуществляется по почте `@sfedu.ru`.
- Science подбирает свежие ИТ-публикации при подготовке каждой РПД. Агент преобразует релевантные статьи в предлагаемые учебные темы или практические задания с источниками.
- Черновики, состояние LangGraph, справочник экспертов и вложения должны переживать перезапуск контейнера. Ключи провайдеров задаются в окружении VPS.

Порядок поставки: интерфейс Streamlit и сохранение состояния → пробный сценарий с методистом и экспертом → сборка Docker и проверка запуска → настройка HTTPS на домене и проверка приложения на VPS. Для последнего этапа нужны данные домена и доступ к серверу по SSH.
